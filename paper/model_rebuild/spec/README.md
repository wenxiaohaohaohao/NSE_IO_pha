# Effective Specification Control

## Read order before every Phase

1. `MAH_model_rebuild_effective_spec_v1.2.md`
2. `specification_hashes.md`
3. `instruction_traceability_matrix.csv`
4. `../paper/model_notes/00_model_closure_status.md`
5. relevant symbols, assumptions, dependency-map and open-issues files once Phase 1 creates them

## Reproduction order

1. Run `python paper/model_rebuild/scripts/apply_spec_amendments.py`.
2. Run `python paper/model_rebuild/scripts/build_traceability_matrix.py` to reproduce the approved specification-level matrix. Later Phase evidence updates must be preserved deliberately.
3. Run `powershell -ExecutionPolicy Bypass -File paper/model_rebuild/scripts/audit_spec_checkpoint.ps1 -ExpectedStatus APPROVED`.

The base note is not rewritten from a summary. The effective file is generated by unique-anchor operations against the frozen base. The source files remain immutable.

## Checkpoint rule

The specification checkpoint is `APPROVED`. Its approval authorizes one specification commit and push, followed by Phase 1 only. Every Phase retains its own mandatory approval gate.
